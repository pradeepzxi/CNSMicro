01 What is Password Hashing?

Password hashing is the mathematical application of a cryptographic one-way function to a plaintext password. A one-way function possesses two essential properties:

  • Pre-image Resistance (One-Way): Given a digest H, it is computationally infeasible to calculate the original input M such that hash(M) = H.
  • Deterministic Output: Passing the exact same input through the hash function will always produce the exact same 256-bit (32-byte, 64-hexadecimal-character) digest.
  • Avalanche Effect: Changing even a single bit in the input produces an unpredictable, vastly different output digest.

02 What is Salting?

A salt is a unique, cryptographically random sequence of bytes generated for each user credential during registration. In this system, os.urandom(16) produces 16 bytes (128 bits) of cryptographic entropy directly from the OS kernel CSPRNG.

The salt is concatenated with the password bytes prior to hashing:

data = salt + password.encode("utf-8") password_hash = hashlib.sha256(data).hexdigest()

The salt does not need to be kept secret and is stored alongside the hash in users.json. Its purpose is to guarantee uniqueness across stored hashes.

03 Why is the Original Password Not Stored?

Storing plaintext passwords represents a catastrophic single point of failure in computer systems. If a database is breached, leaked, or inspected by unauthorized personnel:

  • Plaintext passwords immediately expose users across all services where they may reuse passwords.
  • By storing only {salt, hash}, the server authenticates users by re-computing the mathematical transformation, verifying identity without ever needing to know or preserve the secret itself.

04 How Registration Works

The registration protocol proceeds in strictly defined sequential steps:

  • Input Validation: Verifies the username is non-empty and does not already exist in users.json. Enforces a minimum password length of 6 characters.
  • Salt Generation: Generates a fresh 16-byte random salt using os.urandom(16).
  • Hash Computation: Combines salt + password.encode("utf-8") and executes hashlib.sha256().
  • Persistence: Encodes the salt to a 32-character hexadecimal string and writes {"salt": salt.hex(), "hash": password_hash} to users.json.

05 How Login Works

The authentication verification protocol follows zero-knowledge validation principles:

  • Credential Lookup: Retrieves the stored record for the given username. If no record is found, authentication immediately fails.
  • Salt Extraction: Converts the stored 32-hex-character salt back to raw bytes using bytes.fromhex(stored_salt).
  • Dynamic Re-Hashing: Computes hashlib.sha256(salt_bytes + entered_password.encode("utf-8")).hexdigest().
  • Constant-Time Comparison: Compares the computed hash with the stored hash using hmac.compare_digest() to mitigate side-channel timing attacks.
  • Enumeration Prevention: Any failure returns a uniform message ("Invalid username or password.") to prevent attackers from discovering valid usernames.

06 Why Different Salts Produce Different Hashes (Rainbow Table Defense)

Without salting, if two users choose the identical password "Password123", both stored hashes would be identical. An adversary could precompute a lookup dictionary of common passwords and their SHA-256 hashes (a Rainbow Table) to immediately reverse entire databases.

With random salting, even if 10,000 users have the same password, each user receives an independent 128-bit random salt. This makes the probability of two users sharing the same salt 1 in 2^128 (virtually zero). Precomputed tables become completely useless, as the attacker must recompute an entire table specifically for every individual user's salt.

07 Academic Implementation vs. Production Security

While SHA-256 + random salting satisfies academic criteria for demonstrating cryptographic one-way properties and entropy injection, standard SHA-256 is designed to be computationally fast. Fast algorithms can allow modern GPU clusters to compute billions of candidate hashes per second in offline brute-force dictionary attacks.

In modern enterprise production systems, password hashing relies on deliberately slow, memory-hard Key Derivation Functions (KDFs):

  • Argon2id: Winner of the Password Hashing Competition (PHC); provides memory-hardness and side-channel resistance.
  • bcrypt: Adaptive hashing function based on the Blowfish cipher with configurable work factor iterations.
  • scrypt: Specifically engineered to require significant RAM, defending against custom ASIC/FPGA hardware attacks.
  • PBKDF2: NIST-standardized key derivation applying HMAC repeatedly with high iteration counts.
